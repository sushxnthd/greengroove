Green
Groove

A supermarket checkout experiment that became a systems project about identity, sensing and keeping physical and digital state aligned.

Explore the system → See validation

The premise

Checkout starts before checkout.

If a store can observe a product leaving a shelf, Green Groove asks whether that event can become the beginning of a transaction instead of something ignored until the customer reaches the counter.

See how the system works →
System architectureFour hand-offs

One shopper.
One session.
Many shelf events.

The system builds the transaction gradually while the trip is happening. Each hand-off contributes state instead of reconstructing everything at the end.

01

Identify

An RFID-enabled wristband establishes one persistent shopper session.

02

Sense

Shelf-side hardware detects a product being picked up or returned.

03

Associate

The physical event is linked to the shopper and updates the live digital cart.

04

Settle

The accumulated state supports billing and inventory updates at the end.

shopper identity→shelf event→live cart→billing state
Engineering notesWhere the project got interesting

The happy path was easy.
The edge cases changed the project.

Once we stopped treating Green Groove as a smart object and started treating it as a stateful system, the important questions became about ambiguity, reversibility and trust.

Returns

Every forward action needs an inverse.

Putting an item back must reverse the exact cart state created by the original pick event. Returns cannot be treated as an afterthought.

Sensor disagreement

Uncertainty should stay visible.

RFID evidence and shelf-state change may not arrive together or may point to different interpretations.

Simultaneous actions

Detection is not association.

Nearby shoppers can create overlapping events. The system must determine not only what moved, but whose cart should change.

Persistent identity

Re-identifying the shopper at every shelf would recreate the same problem.

The shopper identity has to persist across the trip, so one session can absorb many shelf events without repeatedly guessing who caused them.

My contributionCo-creator

I worked across the project, not inside one box.

The project moved between research, systems thinking, interaction design and prototype communication. That range is part of what made it useful.

01

Research

Mapped supermarket friction points and narrowed them into a system problem we could design around rather than a generic “smart retail” concept.

02

Architecture

Helped shape the identity → shelf event → cart state → settlement flow and the logic around returns, disagreement and ambiguous events.

03

Interaction

Designed how the band, shelf and digital cart should behave as one experience rather than three disconnected products.

04

Prototyping

Built the visual and product artifacts used to explain the concept, expose weaknesses and iterate on it.

What changed

The first version was about a smart object. The better version was about keeping several states synchronized.

Green Groove made me think less about isolated “smart” products and more about systems: what each component knows, when it knows it, what can go wrong, and how a physical action becomes trusted digital information.

That systems perspective became more valuable than the original branding exercise.
